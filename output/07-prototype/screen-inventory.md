# HCM One: Screen Inventory (Chat-First Architecture)

## 1. Summary

Proposed for Gate G07. In accordance with the Project owner's direction, HCM One features a **chat-first conversational interface with rich inline cards** across two role-specific surfaces, using a **single unified responsive layout system** and a **dedicated high-contrast dark theme**:
1. **`CHAT-HR` — HR Admin Chat Workspace:** A continuous conversational stream where the HR administrator enters payroll requests via typed text or suggestion chips. The assistant replies using approved sentences (C01–C29) and embeds interactive rich cards in the chat. Heavy review tasks (multi-month arrears breakdown tables, full settlement component lists, bonus employee scope tables, and calculation proof) open in an integrated contextual panel/sheet (`PANEL-HR`).
2. **`CHAT-EMP` — Employee Chat Workspace:** A conversational surface where employees ask about changes to their take-home pay, tax deductions, or company payroll rules. The assistant explains causes using approved sentences and inline cards (hero numbers, ranked reasons, query drafts). Deep calculation proof, evidence reviewers, and settlement statements open in fluid contextual panels/sheets (`SHEET-EMP`).

**Unified Responsive Layout System (DEC-038):**
- **Desktop (1024 px and wider):** Full-width chat workspace with a right side panel (width 480 px) for calculation proof and dense detail.
- **Tablet (768 to 1023 px):** Same layout with side panel wider (520 px) and overlaying the chat thread.
- **Mobile (below 768 px):** Chat thread fills the screen; the side panel transitions seamlessly into an accessible bottom sheet; composer remains docked at the bottom; tables switch to a stacked card layout with `data-label` headers so nothing scrolls sideways.
- **Removal of Fixed Phone Frame:** The fixed phone frame container has been removed. The employee chat looks like the HR chat on desktop, and both adapt gracefully across all smaller screen widths.
- **Identical Functional Parity:** All content, wording, cards, numbers, actions, and rules remain 100% identical at every viewport size. Breakpoints and layout values are defined as CSS variables in `tokens.css`.
- **Accessibility:** Touch targets are at least 44 px on mobile viewports. Focus trapping and escape-key dismissal work across both the desktop side panel and mobile bottom sheet.

**Dark Theme Only (DEC-039):**
- HCM One operates in a single, high-contrast dark theme (`#0B0F19` deep slate navy page background, `#111827` surface cards, `#F8FAFC` primary text) configured purely via tokens in `tokens.css`. No light theme and no theme toggle.
- Deep teal brand accent (`#14B8A6`), hover (`#2DD4BF`), and status colors are optimized for dark backgrounds. All text, numbers, and UI elements meet WCAG 2.2 AA contrast (minimum 4.5:1; text primary > 17:1). Status is never conveyed by color alone.

General payroll concepts (e.g., *"What is LOP?"*, *"What is PF?"*, *"What is Gratuity?"*) are answered directly in the chat using a structured **Payroll FAQ Knowledge Source** formatted to the course dataset schema (`id`, `category`, `question`, `answer`, `link_text`, `url`), with answers sourced strictly from the approved payroll glossary in `output/06-ai-interaction/conversation-design.md`.

**Traceability & Compliance:**
- **Zero Frontend Math:** Every number rendered inside any card or panel originates exclusively from deterministic engine calculations in `data/generated/scenarios/` and is verified by automated tests against the backend API (DEC-033).
- **Approved AI Copy Only:** The assistant outputs strictly approved copy (C01 to C29) corresponding to authorized role boundaries. No LLM hallucinations, paraphrasing, or conversational filler.
- **Explicit Human Governance:** Actions such as approving proposals, editing parameters, and submitting queries require explicit user clicks with distinct disclaimers (e.g., C04 approval disclaimer; approval never resembles payment).
- **Strict Information Security:** No "Verified" badges. No file paths, screen IDs, rule keys, or sentence codes are visible to users. Query statuses are strictly: `Draft`, `Sent`, `In review`, `Resolved`, `Closed`.
- **Future-Proof Agentic Handoff:** Intent routing maps typed input to demo intents today and is architected so an agentic framework (e.g., CrewAI classifier, retrieval, and response crew) can replace the prototype intent matcher without altering card schemas or conversation contracts.

Sources: [current BRD v1.2](../../input/requirements/Payroll_brd_v1.2.md), Sections 3, 5–9; [approved user flows](../05-architecture/user-flows.md); [approved edge cases and states](../05-architecture/edge-cases-states.md); [AI interaction artifacts](../06-ai-interaction/); [design decision log](../../project-memory/design-decisions.md), DEC-007 through DEC-039.

## 3. Mapping of Previous Screens (SCR-01 to SCR-06) to Chat

| Previous Screen ID & Name | Previous Role & Form | New Chat Surface & Interaction Mechanism | Justification for Chat Transformation |
|---|---|---|---|
| **SCR-01**<br>Prepare a proposal | HR Desktop standalone form page | **`CHAT-HR` thread:** HR types a request (e.g., *"Prepare Priya Sharma's pending back-dated hike."*) or taps a suggestion chip. Assistant displays C01 intro, asks clarifying question C02 if date is missing, and displays an inline **Proposal Summary Card** with populated contractual inputs from `display_inputs`. | Eliminates redundant empty form pages. Conversational capture feels natural while retaining strict schema validation before calculation. |
| **SCR-02**<br>Review a proposal | HR Desktop heavy review page with drawer | **`CHAT-HR` thread + `PANEL-HR`:** Assistant replies with C03 and renders proposal status, certainty badge, Hero Net Arrears Card, Gross/PF/TDS Cards, and Approval Card (C04). Clicking *"View full month breakdown"* or *"Show calculation"* opens **`PANEL-HR`**. | Keeps the conversation lightweight and uncluttered while giving full desktop space to multi-month tables and proofs in the side panel. |
| **SCR-03**<br>Review a payroll query | HR Desktop standalone review table | **`CHAT-HR` thread:** HR asks *"Show pending queries"* or taps chip. Assistant renders an inline **Query Status Card** (employee ID, issue category, description, attached evidence) and resolution action. | Integrates query resolution directly into HR workflow without requiring a separate portal or dashboard. |
| **SCR-04**<br>Understand my payroll | Employee Mobile card stack | **`CHAT-EMP` thread:** Employee asks *"Why is my take-home pay lower in September?"* Assistant responds with C27, renders Hero Net Pay Card, Net Change Card, and **Ranked Reason List Card**. Clicking *"Show calculation"* opens **`SHEET-EMP`**. Asking for colleague's pay triggers Refusal Card with C10. | Replaces rigid dashboards with an interactive dialogue that directly answers employee confusion and reduces payroll ticket load. |
| **SCR-05**<br>Review my query draft | Employee Mobile draft editor | **`CHAT-EMP` thread:** Tapping *"Draft a query for HR"* from `CHAT-EMP` converts context into an inline **Query Draft Card**. Assistant asks C12 (*"Send this query with the listed evidence to HR?"*). Tapping *"Review evidence"* opens evidence in **`SHEET-EMP`**. Confirming send submits the query. | Keeps query drafting immediately adjacent to the explanation that prompted it, preventing context loss. |
| **SCR-06**<br>Track my payroll query | Employee Mobile status timeline | **`CHAT-EMP` thread:** Employee asks *"Check my query status"*. Assistant renders an inline **Query Status Card** displaying live lifecycle state (`Draft`, `Sent`, `In review`, `Resolved`, `Closed`), HR reply text, and dispute/close buttons. | Eliminates static ticketing screens; query progress is tracked conversationally with instant access to historical responses. |

## 5. Screens Considered & Removed in Chat-First Pivot

| Traditional Screen / Concept | Treatment in Chat-First Design | Architectural Rationale & Principle Source |
|---|---|---|
| **Multi-page HR Admin portal** | Replaced by single unified `CHAT-HR` surface | Eliminates fragmented navigation. The HR administrator maintains complete situational awareness in one scrolling conversation while offloading complex comparisons to the side panel. (UXP-01, UXP-04) |
| **Static employee payslip viewer** | Replaced by conversational `CHAT-EMP` feed | Rather than forcing employees to inspect dense tax tables, the assistant answers questions directly, leads with the net pay outcome, and provides ranked causal reasons. (UXP-03, PS-01) |
| **Separate ticketing / query forms** | Replaced by inline Query Draft Card & Status Card | Keeps inquiry drafting immediately adjacent to the disputed explanation. Pre-populates evidence without human transcription errors. (F6-01–F6-09) |
| **Standalone calculation proof pages** | Embedded into Right Side Panel (`PANEL-HR`) and Bottom Sheet (`SHEET-EMP`) | Ensures explainability is accessible on-demand from any number card without losing conversation context or creating navigation dead-ends. (FR-1.10, FR-4.10) |
| **Dashboard charts and predictive metrics** | Completely omitted | Outside BRD v1.2 scope. Predictive payroll numbers violate the strict deterministic engine guarantee. (DEC-033) |
