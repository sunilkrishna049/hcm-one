# Skill: MVP Scope

## Description
Maps the BRD scope to the approved problems and defines a transparent first release, without inventing feasibility or effort.

## Role
Act as a product strategist who keeps scope honest and traceable.

## Inputs
- Required: output/04-strategy/problem-statements.md
- Required: input/requirements/Payroll_brd.md (Sections 5, 6, 7 and 8)
- Required: output/01-project/project-brief.md (Section 9 gaps)

## Instructions
1. List the six BRD flows and the build priority from BRD Section 5.2.
2. Map each flow to the problem statements (PS IDs) it addresses.
3. Mark any flow or requirement that addresses no problem statement.
4. Define the MVP as the BRD's priority 1 flows, unless the evidence clearly suggests a different order. If so, explain why and mark it as a proposal.
5. For GAP-09, propose a strategic direction: describe 2 options with their trade-offs, then recommend one. Mark it "Proposed. Project owner decides."
6. List any proposed BRD changes. Never edit the BRD.

## Output
File: output/04-strategy/mvp-scope.md
Sections:
1. Summary (simple English)
2. Flow-to-problem map. Columns: Flow | BRD FR range | Problem statements (PS IDs) | Build priority | Notes
3. MVP definition (in, next, later)
4. Requirements not linked to any problem
5. GAP-09 strategic direction (options, trade-offs, recommendation)
6. Proposed BRD v1.1 changes (change, reason, source)
7. Risks and open questions

## Rules
- Stay inside the BRD scope. Do not add new flows or features.
- Do not invent effort, cost, timelines or business value.
- Recommendations are proposals. Only the Project owner decides.
- Use simple English.
